# 得分点覆盖与路径选择

> 先跑 `redteam_score_list` 拿当前靶标的实际 code / 上限 / 档位 / 已用额度（`cap_used` / `capped` 是停止信号）。
> 本机 25 条得分点与 8 条通用规则 G1–G8 的**口径原文**在 `lib/redteam/score-rules.js`：每条 code 有 `need`（算不算权限）、`proof`（要什么证据）、`replay`（复现材料）；本技能只给“怎么识别、先打哪、要什么证据”，不替代工具返回。
> 原则：**先算分值 ÷ 投入**，再决定打哪条；服务器权限是进内网的跳板，不是唯一目标。

> **账号类红线**：`web-app` / `central-system` / `file-storage` 记分必须带 `access_id`（`redteam_access_add` 记录的真实登录：host/username/method）。只探测到未授权接口、响应里有数据、只拿到凭据，都不算账号权限——按漏洞或 `redteam_data_proof` 记，不记账号分；WebShell/RCE 会话（method 含 shell/rce）也不能当账号登录。
> **范围红线**：过 `redteam_scope_check` 得 `out` 的资产不落库、不计分。

## 1. 域名控制（domain-control）

- 识别：目标主域/子域的注册商、DNS 托管、CNAME、证书、WHOIS。
- 路径：注册商/DNS 控制台弱口令或被盗凭据 → 改解析/加子域；子域接管（CNAME 指向未认领的云资源）；DNS zone transfer；证书签发滥用。
- 证据：控制台截图、解析记录 before/after、WHOIS/备案主体；一级 50 / 二级 20，按域名类型给分。
- 注意：只改可控记录并留证据，不做破坏性解析；不要碰非目标域。

## 2. 终端（terminal-access）

- 识别：打印机、WiFi 路由器、摄像头、电子大屏、PC/Pad/手机、MDM/终端管理后台。
- 路径：默认口令/未授权管理页 → 设备控制；终端管理后台 → 批量终端；AD/MDM 托管节点。
- 证据：设备页面 + 与目标单位的关系（资产标签、单位名称、页面落款）；打印机/WiFi 5 分/台，PC/Pad/手机/摄像头/大屏 10 分/台（G4）；批量给 3 张代表图即可。
- 注意：不要批量锁死设备；不要触碰与业务生产直接相关的控制指令。

## 3. 网络设备（netdev / netdev-redirect / netdev-implant）

- 识别：VPN/SSL-VPN、防火墙、路由器、交换机、网闸、光闸、摆渡机。
- 路径：管理口默认/弱口令、SNMP 社区串、已知 CVE、配置文件泄露；拿到权限后看路由表/策略/连接量。
- 证据（G7）：路由表、策略配置、连接量截图；普通 100 / 管理员 200；重定向/业务劫持 → `netdev-redirect` +200；植入远控并成功后续攻击 → `netdev-implant` +1000，单独记一条。
- 注意：改路由/策略前先备份并记录原值；不做断网式操作。

## 4. 云管理平台（cloud-platform）

- 识别：K8S/OpenShift、云控制台、PaaS 管理端、AK/SK、metadata 服务。
- 路径：API Server 未授权/弱口令、控制台弱口令、AK/SK 泄露、SSRF 打 metadata、CI/CD 凭据。
- 证据：管理员操作（新增节点/改权限）截图；管理员 500；云上主机/容器 10 分/台；节点 <100 按 `web-app`，节点不计分。
- 注意：AK/SK 批量控制默认只算节点分，除非能证明管理员权限。

## 5. 物联网 / 工业互联网（iot-platform / iiot / iot-corenet）

- 识别：摄像头/NVR/门禁/传感器平台、SCADA/HMI/PLC、车联网/智能制造/远程诊断。
- 路径：平台默认口令/未授权 API、设备固件/协议暴露、厂商运维通道；从端点设备横向进核心网。
- 证据：平台控制台、连接点数、设备清单；平台 200、连接点 10/台；经端点打入核心网并控制业务生产 → `iot-corenet` +5000（单独记一条）。
- 注意：不要操作生产控制指令；先在只读页面取证。

## 6. 安全设备（secdev）

- 识别：WAF/IPS/IDS/审计/日志平台（非集权类）。
- 路径：管理口默认口令、CVE、API 未授权；拿到后看策略/日志/资产发现能力。
- 证据：管理员页面、设备型号/权限；管理员 200，上限 1000。
- 注意：集权类（堡垒机/域控/SSO/终端管理）走 `central-system`，不要混。

## 7. 文件存储（file-storage）

- 识别：FTP、SMB/NAS、对象存储（OSS/S3/MinIO）、企业网盘。
- 路径：账号/AK-SK、默认口令、后台登录；**匿名列举/匿名读写/匿名上传只记漏洞或数据，不算存储系统权限**。
- 证据：登录/调用成功（`redteam_access_add` → `access_id`）、账号档位、文件清单；管理员 50 / 普通 10；数据单独计分（G2，用 `redteam_data_proof` 记字段/条数）。

## 8. 模型 / 算力（ai-agent / model-compute / model-data / computepower-*）

- 识别：Agent/skill 平台、Jupyter/Kubeflow/MLflow/Ray、训练数据/知识库、模型权重、算力平台/卡池。
- 路径：管理端弱口令/未授权、API 未授权、提示词注入/工具滥用、对象存储 AK/SK、调度 API。
- 证据：控制/操作 agent 的截图、系统管理权限、知识库/数据量、卡数；`ai-agent` 100–500；`model-compute`/`model-data` 500；知识库/超 1 亿条或 10TB ×2（G5）；算力管理员 500、10 分/卡（G4）。
- 注意：不要真的投毒/破坏训练；用只读或可回滚操作取证。

## 9. 边界突破（boundary-*）

记分前必须回答四问（写进 `evidence`）：入口区 / 落点区 / 跨了什么隔离 / 实际访问到的靶标内网资产。

1. 入口区：互联网/DMZ/办公/生产/隔离？
2. 落点区：隧道/跳板实际到哪个区？
3. 跨了什么隔离：防火墙/网闸/光闸/物理隔离/多网卡跳板？证据是什么？
4. 实际访问到的靶标内网资产：IP:端口 + 回显/协议交互。

同区或四问缺一 → 只记内网范围内的 `server-host`/`central-system`，不要硬凑 `boundary-*`。逻辑隔离 1000、强隔离 10000、物理隔离 30000；`boundary-supply` 还要求用户确认供应商/云服务在范围内，且证明进入主防单位内网（不是只进供应商内网）。

## 10. 通用规则速查（与 `SCORE_GENERAL_RULES` 一致）

- **G1 权限取高只计一次**：同一系统/主机/数据库只按最高权限计一次；先记低档后提权，用 `points` 记高档。
- **G2 数据成果另行计分**：邮件/业务/数据资产按重要程度另记；`evidence` 写实际条数/大小；三要素等敏感信息 **≥1 万条**优先，用 `redteam_data_proof op=add` 记（`row_count>=10000` 会标 `meets_threshold`）；只取证明所需样本，不拖全库。
- **G3 上限**：每条 rule 有上限，`redteam_score_list` 里 `cap_used` 接近 `cap`、`capped` 变多是停止信号，换条/换资产。
- **G4 按台/个**：终端、云节点、物联连接点、算力卡按数量累加。
- **G5 翻倍**：重要数据 >1 亿条或 10TB、控制知识库相关系统倍分。
- **G6 IPv6**：IPv6 成果 ×3，但不突破原上限。
- **G7 证明**：边界要隔离设备/能访问内网截图；网络设备要路由表/连接量；终端要归属证明；集权托管节点要 20%（最多 20 台）。
- **G8 兜底**：规则没覆盖的系统，用 `redteam_score_point_save` 新增自建点，写清判定口径。

## 11. T0–T3 与资产分级（决定“值不值得打”）

- **T0 直接归属**：备案主体/域名注册人/证书 CN 与靶标单位一致；穷尽打法。
- **T1 强相关**：控股子公司、分支机构、同一法人、同一注册人（要有证据）；可打，但证据要写清关系。
- **T2 弱相关**：同 C 段、旁站、同 favicon、共享托管、供应商；**T0/T1 穷尽后才申请**，命中只在下限档记分并注明关系。
- **T3 无关**：不探测、不落库、不计分。

## 12. 选择顺序（作战优先，不只看分值）

1. **P0 能进内网**：能 RCE/命令执行/上传/反序列化，且落点能当跳板（边界/边缘、VPN/防火墙/堡垒机/运维平台、双网卡、对外中间件/上传点）；先拿服务器权限、建隧道、用 `redteam_pivot_probe` 实测进内网。
2. **P1 敏感数据**：未授权接口、已拿账号可访问的接口、数据库/备份，能导出姓名/身份证/手机号等三要素 **≥1 万条**；只取证明所需样本并统计总量。
3. 可直接登录的集权/大数据/业务系统（500–1000 分）。
4. 网络设备/云平台/物联网/安全设备（200–500 分）。
5. 服务器主机/数据库/文件存储（10–50 分；不能进内网时再作为主目标）。
6. 域名/终端（10–50 分，批量或单点）。
7. 边界突破（1000–30000 分，必须四问齐全）。

> P0/P1 是**投入顺序**，不是改写分值；具体分值/上限仍以 `redteam_score_list` 为准。

> 一个资产命中多个 code 时，按“最高权限/最高分值 + 最强证据”记一条（G1）；不要为了凑分在同一服务上刷同类成果。
